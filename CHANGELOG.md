# Changelog

All notable source-controlled changes to the Wardveil Security foundation are recorded here.

## 0.2.0 — 2026-08-18

### Added

- `STATUS.md` interoperable Wardveil security-status semantics.
- `contracts/wardveil.status.schema.json` with fail-closed protected-state and protection-claim constraints.
- Conforming protected and stale/unknown non-sensitive status examples.
- `SECURITY.md` repository security, reporting, evidence-minimization, and sensitive-information boundaries.
- `.gitignore` exclusions for common secret-bearing files and local development artifacts.

### Changed

- Expanded canonical identity, integration, and conformance documentation for normalized states and authoritative evidence.
- Added machine-readable status-contract metadata to the Wardveil identity contract.
- Expanded the zero-dependency validator for foundation version, status semantics, protection-claim rules, repository security controls, legal status, and canonical-icon gating.
- Hardened GitHub Actions validation with read-only permissions, disabled checkout credential persistence, a bounded timeout, and concurrency cancellation for superseded runs.

### Unchanged gates

- Canonical Wardveil icon artwork remains pending and is not generated by this release.
- Wardveil remains blocked from visual showcase until the canonical icon is explicitly approved and stored at `branding/wardveil-security-icon.svg`.
- External name-conflict and legal clearance remain pending.

## 0.1.0 — 2026-08-18

### Added

- Initial Wardveil Security source-controlled foundation.
- Canonical naming and technical-authority boundaries.
- Glaze UI and Privacy Shield relationship definitions.
- Canonical icon description and visual-showcase gate.
- Integration and conformance guidance.
- Machine-readable identity metadata.
- Zero-dependency repository validator and GitHub Actions validation workflow.
